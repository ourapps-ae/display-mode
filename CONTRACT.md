# Display mode

## Purpose and facilities
display-policy: Mode publication and display capability restrictions. Local-development status; the `configuration` requirement is optional.

## User inputs
Supply an initial mode and a nonempty event name. Persistence and authentication belong to the caller.

## Artefacts and dependencies
Every implementation file maps to components/display-mode/ with its implementation/ prefix removed. SOURCE.md records each file's frozen source and line ranges; SOURCE.json records the pinned source hashes. tools.lock.json pins the tool versions. Node 26.5.0 for bundled checks; no runtime language dependencies. Swift and Kotlin sources compile in the consuming application targets.

## Provided interfaces
interfaces/contract.json is an OpenRPC 1.3.2 document for ae/display-policy version 1.0.0: `createMode`, the returned handle's `ModeHandle.current` and `ModeHandle.publish`, and `displayCapabilities` (tagged `typescript`, web/mode.ts), and `DisplayPolicy.canAct`, `canCapture` and `canSeePrivate` (tagged `swift` and `kotlin`), with types as JSON Schema 2020-12. The visual output connector is ae/display-policy version 1.0.0.

## Required interfaces
The `configuration` requirement is optional: the initial mode and event name can be passed in code when the application creates the policy, so a design may leave the port unconnected. The configuration input connector is ae/display-mode-configuration version 1.0.0; interfaces/required-configuration.json is the JSON Schema 2020-12 document of its fields (`initial`, `eventName`). Supply an initial mode and a nonempty event name. Persistence and authentication belong to the caller.

## Integration
See INSTRUCTIONS.md for selection and configuration and suitability.json for the library-only profile. Call createMode once per session, publish the initial mode, and read current() in capture/action callbacks. Publication updates document.documentElement.dataset.mode before dispatching CustomEvent(eventName,{detail:{mode}}). Use native helpers at action/media boundaries. The room service separately enforces authentication and private-data redaction. See examples/consumer.ts.

## Visual definition and connected examples
visual/definition.json is the component block. visual/examples/connected.json wires an illustrative configuration provider and consumer. visual/output/connected.svg and connected.png are generated by the shared format-1 renderer; consumers require neither that tool nor its checkout. visual/output/description.md supplies the text equivalent.

## Infrastructure
No remote service is provisioned by this component. Costs are unmeasured; no deployment is verified.

## Verification
All suites have empty external requirements. Swift and Kotlin compiler availability is checked through each suite's tools declaration; a missing compiler is reported blocked.
Run npm test from the package root. The manifest declares fixtures, exact tools and all additional suites. Local checks require no credentials or sibling source tree. Platform and provider requirements stay explicitly blocked until available; fixture success is not provider verification.

## Scenarios and presentation
Board mode denies actions, capture and private information. Player mode permits capability checks but does not authorize a server request.

## Updates and removal
Patch updates use files-only migration. Caller-owned persisted preferences, desktop partitions and provider rooms are not deleted by removal. Remove generated source references when removing this component. Licence wording remains deferred.
